## v3.2 — 2026-10-05

**加了「检查更新」。以后更新不用再换网址了。**

### 之前为什么麻烦

手机 Safari 没有「强制刷新」这个按钮，下拉刷新也没用 —— 还是同一个网址，照样读缓存。
GitHub Pages 那边缓存最长 10 分钟，所以刚更新完你在手机上看到的可能还是旧版。

### 现在三处入口

| 在哪 | 怎么用 |
|---|---|
| **顶栏版本号**（标题右边那个小 `v3.2`） | **点一下**就检查更新 |
| 设置 → 当前版本 | **点一下**同样会检查 |
| 设置 → 「检查更新」按钮 | 明确告诉你「已是最新」或自动更新 |
| 设置 → 「强制重新加载」按钮 | 页面和脚本全部重新拉一遍（语音包已缓存，不重复下） |

### 怎么知道有没有新版

部署时会自动生成 `version.js`，里面有一个 build 号（像 `202610050033`，就是 2026-10-05 00:33）。

- App 启动时记下自己的 build 号
- 点检查更新时，带时间戳再拉一次 `version.js`（`?t=...`，**必然绕过缓存**）
- 两个号不一样 → 说明线上有新版本 → 自动重载，并在网址后面带上 `?b=新build`

**关键在最后那步**：带上 `?b=` 之后，对 Safari 来说这就是个**从没见过的网址**，缓存一定绕过去。

### 还有个贴心的小动作

切回 App 时（从后台切到前台）会**静默看一眼**有没有新版 —— 有就悄悄更新，不打扰你。
没网或检查失败就当作什么都没发生，不会弹错误。

设置里也会显示当前 build 时间，方便判断手机上跑的是哪一版：
`当前版本：v3.2（2026-10-05 00:33）`

### 验证

|---|---|

| build 号读取、设置里显示时间 | 通过 |

## v3.1 — 2026-10-04

**修掉 v3.0 的语音加载失败。改成断点续传，而且第二次打开不用再下。**

### 你遇到的问题

手机上点朗读，弹出「神经语音包加载失败：。」——**而且失败原因那一格是空的**。

两个问题，都改了：

1. **7.8 MB 一次性下载在手机网络上太脆弱。** 中间断一下就整个失败，还得从头再来。
2. **错误信息被我弄丢了。** 出异常时没把真正的原因带出来，所以只显示一个句号。

### 现在怎么做

- **语音包切成 16 块**（每块 512 KB），一块一块下。
- **每块自动重试 4 次**（间隔 0.4 / 0.8 / 1.2 秒递增）。单块抖动不会毁掉整个下载。
- **下完存在本机（IndexedDB）**，第二次打开直接读本地，秒开、不再走网络。
- **失败会说清是哪一块**，例如「第 4/16 块下载失败（HTTP 404）」。
- 设置里多了两个按钮：**重新下载语音包** / **清掉本地语音缓存**。
- 加载时会显示进度：`正在下载语音包 3.1 / 7.8 MB（40%）`。

### 顺带修的存储 bug

缓存写进 IndexedDB 时用了 `createObjectStore("packs")`，没给 `keyPath`，
结果 `put()` 抛异常：*The object store uses out-of-line keys and has no key generator*。
**是静默失败** —— 缓存永远写不进去。现在改成 `{ keyPath: "id" }`，并把库版本升到 2，
已经建过旧库的设备会自动重建。

实测：缓存 8,133,528 字节写入成功，第二次打开 11 ms 读完、**零网络请求**。

|---|---|
| 分块下载（16 块顺序正确） | 通过 |
| 首次播放（解码 + 高亮） | 7 个音节，通过 |
| 缓存写入（字节数核对） | 8,133,528 字节，通过 |
| 热启动（不再下载） | 11 ms，0 块，通过 |
| 单块失败时的报错 | 「第 4/16 块下载失败（HTTP 404）」，通过 |

## v3.0 — 2026-10-04

**内嵌了一个神经语音模型。不再依赖苹果的婷婷、美嘉。**

### 这次是真的把声音换了

之前只能在系统自带的中文嗓音里挑，iPhone 上就只有**婷婷**和**美嘉**两个，而且都是老式离线嗓音，很机械。

现在 App 里直接带了一个神经网络的语音模型声音。

**做法**：在本机用 Piper 中文神经模型（`zh_CN-huayan-medium`）把普通话全部 **1483 个音节**（四声 + 轻声）预先合成好，打包放进 App。朗读时按字查拼音、拼接播放。**模型不在手机上跑**，所以不占内存、不怕兼容性。

### 好处

- **不依赖系统 TTS** —— iPhone 上也能听到同一个神经模型的声音
- **断网也能读** —— 全部离线，不联网、不花钱
- **不占流量** —— 首次下载后浏览器会缓存
- **点字起读、黄底高亮** 全部保留

### 中文变调都处理了

拼音不是查字典就完事，中文有变调，不处理就很怪：

| 规则 | 例子 |
|---|---|
| 三声连读，前字变二声 | 「你好」→ ni2 hao3、「我很好」→ wo2 hen2 hao3 |
| 「一」在四声前读二声 | 「一件」→ yi2 jian4 |
| 「一」在其他声前读四声 | 「一起」→ yi4 qi3 |
| 「不」在四声前读二声 | 「不对」→ bu2 dui4 |

而且实测发现：**汉语拼音表里根本没有 `wo2` 这个音节**（它只是「我」三声变调产生的）。共有 **96 个这样的变调音节找不到对应汉字**，用生僻字顶替会读错，所以改用**音高变换**从本调派生（用「我」wo3 合成出 wo2）。

### 设置里可以选

「设置 → 朗读与语音 → 用哪个声音读」：

- **华言 · 神经语音**（默认）—— 内嵌模型，推荐
- **系统嗓音** —— 婷婷 / 美嘉，想用旧的切过去

### 实现细节

- 音节包为了避免撞 GitHub 的二级限流，**打成一个二进制包**（`huayan.pack`），部署文件数从 1487 个降到 **2 个**。包头是一张索引表，浏览器拿到后按字切片交给 `decodeAudioData`，零拷贝。
- 打包时踩了一个坑：`json.dumps` 默认 `ensure_ascii=True` 会把中文转成 `\uXXXX`，转义后长度变短，头部记的索引长度和实际写入的差了 4 字节，结果每个音节都错位、全部解码失败。现在头部只编码一次，并在打包时断言校验（首个音节必须是 `OggS`）。

### 没做的事（如实说）

- **林志玲那种音色依然没做** —— 商业授权音源，拿不到。
- **语音包 7.8 MB**，首次使用要等一下（之后缓存）。试过压到 3 MB，但我听不到音质变化，没法判断是否变差，所以没敢用。

点语音键整行变长条按钮，**按住说话、松开结束**。

iPhone 上的语音入口不再"消失"：点它会自动聚焦输入框并提示用**键盘自带的听写**。

修了一个布局 bug：输入框曾被压成 193px（容器用了 `justify-content:flex-end`，导致没有剩余空间，`flex:1` 反而失效）。

## v2.2 — 2026-10-04

**加了朗读、语音输入、QQ 表情。**

### 朗读（可以从句中任意一个字开始）
点一下从头读；**点回复里的任意一个字，就从那里往下读**；按**句子**切块，正在读的那段黄底高亮。

### 语音输入（语音转文字）
识别出的字插到光标位置。安卓 Chrome / 电脑上能用。**iPhone 上系统不允许网页用语音识别**，走键盘自带听写。

### QQ 表情
72 个常用表情，点一下插到光标处；**也支持 `/` 代码**（打 `/微笑` 就出表情）。军师也会用表情回你，可在设置里关掉。

> 为什么不用 QQ 官方表情图片？那些是腾讯的版权资源，自托管有风险。所以用系统 emoji：离线可用、任何手机都显示、微信里也发得出去。

## v2.1 — 2026-10-04

**加了读图功能。**

点「相册」选图、**截图后直接粘贴**、或拖进页面。一条最多 4 张。
发送前自动压缩：最长边 896px、目标 300KB（实测 1.3MB 的手机照片压到 250KB）。
PNG 透明底会先铺白底再转 JPEG，不然会变黑。

> **要看图，模型必须支持视觉。** DeepSeek 官方的 `deepseek-chat` 只认文字。
> 模型不认图时，会自动去掉图、只用文字再问一次。

## v2.0 — 2026-10-04

**修好了手机上打字框会被放大的问题，并把"只有一个对话"的短板补上。**

### 修掉的 bug
1. **打字框一点就放大页面（iOS）**：输入框字号小于 16px，iOS 聚焦时会强制放大网页，失焦后不会自己缩回。现在都顶到 16px。
2. **打字框被占位文字撑成两行**。
3. **历史搜索框被裁**。
4. **旧对话没标题**。
5. **发送失败会污染上下文**：现在把这句话从历史里撤掉、放回输入框。
6. **用户气泡里的代码块黑白撞色**。

### 新增功能
- **多对话 + 历史**：每个话题一个独立对话，自动用第一句话当标题，能搜内容、能删。**旧版本的对话会自动迁移过来。**
- **停止生成**：生成中「发送」变红色「停止」，已收到的部分保留。
- **消息级操作**：复制 / 删除；我的能重发，它答的能重新回答、引用追问。
- **测试连接**：一键验证接口地址 / Key / 模型名。
- **导出当前 / 导出全部**。
- **背景资料不限长度**：人设 + 背景永远完整发送，只截聊天记录（最近 24 条）。
- **未保存提醒**。
